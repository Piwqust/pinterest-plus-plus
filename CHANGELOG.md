## [1.0.7] — 2026-09-10

### Кнопки в сетке — свой оверлей поверх картинки, только под курсором

- **Что:** пара Copy/Download в сетке лежит в свободном верхнем левом углу картинки пина, показывается только при наведении на пин (и при фокусе с клавиатуры) и оформлена как панель ресайза — своя поверхность, свои размеры. В DOM-строки Pinterest мы больше не встраиваемся. В закрытом пине (close-up) панель как была — постоянная и в их баре.
- **Где:** `shared/pin-action-manager.ts`, `shared/media-action-host.ts`, `shared/ui-assets.ts`, `shared/pinterest-dom.ts`, `tests/pin-action-manager.test.ts`, `tests/media-action-host.test.ts`, `tests/pinterest-dom.test.ts`.
- **Почему:** встраивание в чужой флекс-ряд ломалось трижды подряд: кнопки то не появлялись, то мигали, а на последнем скриншоте их размер, снятый с соседней кнопки, не влез в ряд и перенёс собственные контролы Pinterest на вторую строку.
- **Было:** хост вставлялся перед звездой избранного или меню «…», а размер и подложка снимались с соседней кнопки.

### Fixed

- **Мы больше не участвуем в раскладке Pinterest.** `position: absolute` внутри пина не может ничего сдвинуть — ни ряд, ни кнопку, ни при каком составе плитки. Это и есть главное исправление: класс ошибок «поехала вёрстка Pinterest» стал невозможен, а не «починен».
- **Отвергнуто: подстройка под соседей.** Чтение фона, радиуса и размера у соседней кнопки давало 54 px там, где ряд рассчитан на 32, и разъезжалось при любом их редизайне. Вместо мимикрии — собственная панель в языке расширения: та же поверхность, граница и радиус, что у панели ширины плиток.
- **Отвергнуто: якорь на контрол Pinterest.** Плитка пересобирается на каждое наведение, и хост приходилось вставлять заново, гоняя `MutationObserver`, запасные оверлеи и наборы состояний. Оверлей крепится один раз к самому пину и переживает ререндер; если его всё же выбросили — скан и наведение возвращают его.
- **Угол выбран по свободному месту.** Save у Pinterest справа сверху, «Visit site» слева снизу, поделиться и «…» справа снизу; верхний левый угол свободен на всех типах пинов.
- **Позиция считается от самой картинки.** Оверлей крепится к ближайшему позиционированному предку медиа; свой `position: relative` мы ставим только пину, который не позиционирует ничего сам. Координаты пересчитываются в момент показа — картинка могла догрузиться, а сетка измениться.
- **Клик по кнопке больше не открывает пин.** Пин — это ссылка, и `stopPropagation` её не останавливал: добавлен `preventDefault` на хосте.
- **Показ идемпотентен.** Видимость выводится из текущего состояния курсора и фокуса, а не из перехода в него: хост, вставленный заново на уже наведённом пине, показывается сразу. Именно этот баг давал «кнопок нет, пока не уведёшь и не наведёшь снова».
- **Скрытие — `opacity` в шадоу-CSS.** Кнопки не видно и не нажать; никакого влияния на соседей у оверлея нет по построению.
- **Клавиатура.** `focusin` показывает кнопки так же, как наведение, иначе Tab уводил бы фокус на невидимый контрол.
- **Мёртвый код убран.** `findGridItem` и `findFavoriteControl` больше никому не нужны и удалены вместе с их тестами.

## [1.0.6] — 2026-09-09

### Готовность к ревью: минимальный Chrome и живая кнопка на панели

- **Что:** `minimum_chrome_version` поднят до 111, у иконки на панели появился попап, чтение настроек больше не может уронить content script.
- **Где:** `wxt.config.ts`, `entrypoints/popup/`, `shared/settings.ts`, `tests/settings.test.ts`.
- **Почему:** заявленный Chrome 109 пропускал браузеры, где ключ `world: "MAIN"` ещё игнорируется, а иконка на панели не делала ничего.
- **Было:** `minimum_chrome_version: '109'`, `action` без `default_popup` и без `onClicked`.

### Fixed

- **Chrome 111 вместо 109.** `world: "MAIN"` на манифестном content script читается только с 111. На 109–110 мост к масонри уехал бы в isolated world и ресайз молча не работал — половина продукта без единой ошибки в консоли.
- **`readSettings` больше не отвергается.** Первый `await` в content script был его единственной точкой отказа: профиль с запрещённым sync storage оставался без кнопок и без ползунка, хотя ширина по умолчанию его бы устроила.

### Added

- **Попап без новых разрешений.** Он пишет тот же ключ `tileWidth` в `chrome.storage.sync`, а content script уже слушает `storage.onChanged`, поэтому сетка перестраивается сама. Отвергнут вариант с `tabs` или `activeTab` ради определения текущей вкладки: лишнее разрешение ради косметики удорожает ревью.
- **Потолок ползунка в попапе растягивается под сохранённое значение.** Без этого простое открытие попапа у пользователя с широкими плитками тихо урезало бы его настройку.

## [1.0.5] — 2026-09-09

### Пакет для первой публикации в Chrome Web Store

- **Что:** расширение можно отправлять в Chrome Web Store: ZIP текущей сборки, тексты листинга, обоснования разрешений, политика конфиденциальности как страница, скриншоты и промо-плитки нужного размера.
- **Где:** `store/`, `PRIVACY.md`, `README.md`, `.output/pinterest-plus-plus-1.0.5-chrome.zip`.
- **Почему:** манифест и иконки уже были; без листинга, публичного URL политики и графики дашборд не принимает item. Локальная обработка медиа и `chrome.storage.sync` всё равно считаются handling user data.
- **Было:** README «Load unpacked», короткий `PRIVACY.md`, ZIP без сопроводительного пакета.

### Added

- **Пакет `store/`, а не правка манифеста.** Листинг, политика-HTML и ассеты живут рядом с репозиторием и не попадают в ZIP расширения. В ZIP нечего добавлять для магазина: CWS читает манифест из пакета и поля из дашборда.
- **Политика покрывает локальную обработку.** CWS User Data Policy требует disclosure даже если ничего не уходит на сервер разработчика. Отвергнуто «нам политика не нужна, мы ничего не собираем» — `storage` и чтение URL пина при клике этого достаточно.
- **Скриншоты с реальным CSS контролов, не live Pinterest.** Нужны 1280×800 без чужих пинов и логотипа Pinterest. Отвергнут захват pinterest.com: копирайт чужих пинов и риск, что ревьюер сочтёт это чужим брендом.

### Changed

- **Английский листинг как основной.** UI расширения на английском; русские тексты лежат рядом как опциональная локаль, без `_locales` в пакете. Иначе магазин обещал бы русский продукт, которого в интерфейсе нет.
